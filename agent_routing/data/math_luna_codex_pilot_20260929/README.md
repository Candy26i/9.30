# Codex Luna Math Expert SFT Dataset

This published bundle is included in the repository. Follow the **[complete experiment runbook](../../docs/MARGENT_END_TO_END_RUNBOOK.md)** for the shared RunPod environment and training commands; no separate ZIP upload or old data branch is required.

Questions come from NuminaMath-1.5. Role supervision was generated by Codex tasks with selected model `gpt-6-luna`. The original 160 questions produced 640 supervised rows. After excluding 24 train questions under a mechanical encoding rule, the retained bundle contains **136 questions and 544 rows**:

| Expert | Train | Dev | Supervision |
|---|---:|---:|---|
| Extractor | 104 | 32 | Givens, variables, constraints and goals |
| Reasoner | 104 | 32 | Solution approach and mathematical derivation |
| Verifier | 208 | 64 | Two candidate audits per question |

## File formats and contents

- **`sft/` is the canonical repository-trainer input.** Six JSONL files, each line a complete example, plus manifests, teacher evidence and provenance checks.
- **`json/` contains six ordinary JSON arrays.** Each example has `messages` and limited provenance metadata. Retained prompt/answer messages match `sft/` exactly; conversion did not regenerate answers.
- **The complete local ZIP is an archive, not a required training input.** It additionally contains the raw 30,000-question Numina prefix, per-batch orchestration and quarantine material. That ZIP is not included in this Git publication; its name/hash is in `PUBLICATION.json`.

Use `EXPERT_DATA="$LUNA_DATA/sft"`, not `json/`, with `runpod_expert_sft.sh`. Other frameworks can import `json/*.json` messages with assistant-only loss, the same chat template and the specified role/split boundaries; the exports do not imply integration with those frameworks.

`sft/teacher_requests.jsonl` and `sft/teacher_responses.jsonl` retain evidence for all 960 generation tasks and import attempts. They are not 960 additional supervised examples. `manager/` contains the separate frozen 128-question train / 64-question dev pool and AIME2026 30-question / BeyondAIME 100-question tests. Use the complete pool for expert isolation checks and the runbook's declared subsets for later Manager training. External tests must remain outside collection/SFT/GRPO.

## Validation

After loading the runbook's environment file and changing to the package directory:

```bash
"$EXPERT_PYTHON" "$LUNA_DATA/validate_data.py"
```

This validates hashes, teacher provenance, source isolation, retained counts and equivalence of JSON exports. It does not load the student model, call a teacher or certify mathematical quality. `SHA256SUMS` covers the current published files; documentation-only revisions update the README entry without changing data/provenance hashes.

## Quality and provenance

- Original teacher content is unchanged. The retained subset excludes questions with U+0000..U+001F control characters other than newline in prompts/candidates/responses, consistently across all three roles. This is mechanical filtering, not selection by answer correctness.
- All 544 retained rows passed the actual student-tokenizer check; the longest is 1678 tokens against the configured limit of 8192. This demonstrates readable/tokenizable inputs, not successful 9B CUDA training.
- Every row has `reviewed=false`. A text heuristic flags 15 Reasoner rows as potentially incomplete; this is not a verified error count. The Verifier distribution of 184 correct / 64 incorrect / 24 uncertain contains teacher labels, not independent accuracy measurements.
- Report the source as **Codex subagent synthesis, selected model gpt-6-luna**. Actual backend model, token usage and sampling parameters were not independently observed and remain null. Batch context was shared; candidates and audits were generated separately but may still have correlated errors.
- Some files in `reports/` describe the original complete local archive. Do not assume every source file mentioned there is published here. `PUBLICATION.json` defines the uploaded scope. This bundle alone is not benchmark-improvement evidence.
