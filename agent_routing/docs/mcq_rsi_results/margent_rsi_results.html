MARGENT 多轮 RSI 结果

这页写给读过 MARGENT 论文、但没跟进之后工作的人。论文训练了一个 manager，判断每道题要不要调用 Extractor、Reasoner、Verifier 这三个子模型（论文里叫 advisor）。之后我们做了两件事。一是查清了论文实验里子模型的真实设置。二是在论文的四个多选基准上加了多轮自我改进（RSI），并做了消融。下面先给结论，再讲方法、数据和需要注意的地方。

0结论速览

10 月 8 日更新（第 8、9 节）。7.1 节找到的问题已经修掉并重跑：SFT 不再对 manager 自己的草稿字母计算损失，只训练"调用谁 / 不调用"的路由决策（draft_supervision = none，下文叫 v3）。修掉之后的结论比原来干净，也比原来保守：

  • dynamic 第 3 轮在四个基准上都和 S₁ 持平（差 0.0 到 +0.4 个点，p 全部大于 0.8），同时调用显著减少：MedQA 每题 0.36 → 0.15 次（−58%），MMLU-Pro 0.35 → 0.27 次（−24%）；GPQA 和 AQuA 的调用不变。草稿准确率和字母分布不再漂移（8.3 节）。
  • 重新收集仍然有用，但只在 MMLU-Pro 上看得到。v3 的 static 第 3 轮在 MMLU-Pro test 上比 S₁ 低 6.0 个点（p < 0.001），dynamic 比 static 高 6.4 个点（p < 0.001）。其他三个基准 dynamic 和 static 差别不显著。
  • v1 里 dynamic 的两处"优势"没有保住。AQuA 第 3 轮的 +3.1（原 +4.3）不再显著；MMLU-Pro test_paper 上 dynamic 不再高于 S₁（+0.2），v1 的 +3.2 里混着训练题重叠（4.3 节）。
  • 继续跑到第 5 轮，dynamic 变差、static 不变或变好。MedQA：dynamic 第 5 轮 77.4（对 S₁ −1.0，不显著），static 81.0（对 S₁ +2.6，p = 0.02，和 v1 的 80.4 一致，用 37% 的调用量追平 success 的 80.2）。AQuA：dynamic 第 5 轮 71.7（对 S₁ −5.9，p = 0.009），static 77.2（持平）。这次 dynamic 的下滑和草稿无关（草稿准确率、字母分布都不变），变化在路由上：MedQA 的调用从 Reasoner 转向 Extractor，AQuA 在初稿错的题上少调用了 Verifier；固定调用次数的回放里，两者第 5 轮的挑题都不再高于随机，static 则高于随机（第 9 节）。MMLU-Pro：dynamic 第 5 轮 61.4（对 S₁ −2.6，不显著；对自己的第 3 轮 −3.0，p = 0.04），static 58.0（不变，对 S₁ −6.0）；第 5 轮 dynamic 仍比 static 高 3.4 个点（p = 0.049）。v1 里 dynamic 第 5 轮涨到 67.0 的结果在 v3 里没有复现。
  • 中间版本 v2（只在 call 行掩码草稿，commit 行照旧）会让模型偏向直接作答：MMLU-Pro 第 2 轮的 dev 调用率掉到 0.07，AQuA 的 static 比 S₁ 低 8.7 个点。v2 在 AQuA 上的 dynamic 82.7（+5.1，p = 0.012）是全部实验里 success 之外最高的数，但 v3 没有复现（78.0），我们不把它当结论（8.4 节）。

下面的速览是 10 月 3 日的版本，对应第 1–7 节（论文的选标签规则，含 GRPO）。

  • 复现
    论文的 manager（下文叫 S₁）在我们的流程里能复现论文。GPQA 和 AQuA 在锁定测试（事先登记、每个模型只测一次的测试集）上和论文一致，分别是 54.0 对 54.0、77.2 对 76.8。MedQA 和 AQuA 的 dev 准确率比论文低 2.5 和 5.2 个点，人工核对后放行（第 3 节）。论文实验里的子模型实际上是基础模型加角色提示词，本文沿用这个设置（第 1 节）。
  • dynamic 对 S₁
    每轮用当前模型重新收集数据、重新选标签的 dynamic 跑到第 3 轮后，四个基准上的准确率都没有显著低于 S₁。每题调用次数都有显著变化：MedQA 少 36%，MMLU-Pro 少 22%，AQuA 多 13%，GPQA 多 23%。
  • dynamic 对 static
    static 每轮复用 S₁ 原来的训练标签，不重新收集。两者谁更好取决于基准。MMLU-Pro 上 dynamic 显著更好，test 上的差距从第 3 轮的 5.6 个点扩大到第 5 轮的 8.8 个点。AQuA 第 3 轮 dynamic 高 4.3 个点，处在显著的边界上，第 5 轮两者打平。MedQA 第 5 轮 static 显著更好（+4.0），原因是 dynamic 的选标签规则会把 manager 自己的错误草稿当作训练目标，几轮之后草稿向字母 B 坍缩（7.1 节）。GPQA 差别不显著。
  • 挑题能力
    在 dev 上固定调用次数、和随机调用比较：dynamic 在 MedQA 和 MMLU-Pro 的第 3、5 轮以及 AQuA 第 5 轮都高于随机，说明它挑的题比随机好。AQuA 第 3 轮刚好落在随机区间的上沿，GPQA 都在区间内。S₁ 在 MedQA 上本来就高于随机，static 只在 MedQA 第 5 轮高于随机。
  • success
    只要最终答对就当示范的 success 准确率最高：MMLU-Pro test 71.0、AQuA 83.9，都显著高于 S₁。代价是几乎每题都调用（每题 0.93–1.00 次）。
  • GRPO
    每轮 SFT 之后的 GRPO 经常因为拿不到训练信号被拒（MedQA 7 次全拒），主实验 22 次 GRPO 里有 12 次被回退保护截断。锁定测试上没有找到 GRPO 有显著贡献的干净证据（第 6 节）。
  • 更多轮次
    从第 3 轮接着跑到第 5 轮，只有 MMLU-Pro 的 dynamic 显著变好（test +3.0，test_paper +3.8）。AQuA 和 MedQA 两组都没有显著提升。GPQA 没有剩余的题，没有跑。

1相对论文的变化

1.1 论文里的子模型其实是基础模型

论文为每个基准训练了三个子模型 LoRA（Extractor、Reasoner、Verifier），用 vLLM 加载后调用。我们发现 vLLM 0.26 加载多模态的 Qwen3_5ForConditionalGeneration 时，会静默丢掉键名为 base_model.model.model.layers.* 的 LoRA 权重。所以论文实验中的子模型实际是基础模型加上各自角色的提示词，论文的数字、S₁ 和它的第 1 轮训练标签都来自这个设置。把键名改成 language_model 后 LoRA 才真正生效。

我们接着在每个角色 754 道 dev 题上做了 A/B 测试，比较基础子模型、真正加载的论文 LoRA，以及用验证集加早停重新训练的 v2 LoRA。两种 LoRA 都没有明显好于基础模型，而且训练过的 Verifier 都会把更多原本答对的题改错。因此本文所有实验都使用基础子模型，数字可以直接和论文对照。

1.2 从单轮训练到多轮自我改进

论文训练一次 manager 就结束了，那个模型在本文里叫 S₁。第 1 轮不重新收集数据，也不做 SFT，只在 S₁ 上做一次 FA-GRPO，通过 dev 验收后得到 G₁，各组共用。从第 2 轮起，各组每轮重复下面五步，第 k 轮从上一轮的结果 Gk−1 开始。所以第 3 轮的模型经过了 2 次按组重新选标签和 SFT，第 5 轮的模型经过了 4 次。

  1. 重新收集用 Gk−1 对本轮的收集题先出初稿，再把每种调用方式都试一遍，记录哪些能答对。这就是论文的反事实收集。static 不做这一步。
  2. 选标签按该组的规则，为每道题选一条示范轨迹（见 1.3 的表）。
  3. SFT从 Gk−1 继续做 SFT，得到 Sk。
  4. FA-GRPO从 Sk 出发做最多 64 步强化学习（方法见下段），得到候选 Gk。
  5. dev 验收候选同时满足下面五条才被采用，否则这一轮用 Sk。

五条验收条件：dev 准确率比 Sk 低不超过 1 个点；每题调用比 Sk 多不超过 0.15 次；call gap 不低于 Sk 的一半（call gap 是初稿答错的题的调用率减去初稿答对的题的调用率，衡量调用是否用在该用的地方）；dev 上没有无效答案；训练信号不低于 15%（见第 6 节）。

FA-GRPO（finite-action GRPO）是针对这个任务设计的 GRPO。manager 每一步可选的动作有限，所以奖励期望可以精确求和，不用采样。策略梯度只用来训练 manager 拿到子模型输出后怎样修改答案。要不要调用这一步不加策略梯度，只用 KL 约束它贴近 Sk，另外加一项权重 0.03、只针对路由的 SFT 锚定损失。原因是在答对得 1 分、调用不扣分的奖励下，每题都调用永远是最优策略，直接优化调用决策会重现论文附录 D 里调用次数暴增的崩溃。训练中每 8 步检查一次，调用率变化超过 0.10 或 KL 超过 0.05 时，退回上一个合格的检查点（或 Sk），并结束这一轮 GRPO。

1.3 四种选标签规则（实验组）

组每轮重新收集每道题的示范怎么选这一组用来检验什么
dynamic是初稿已对时直接提交，不调用。初稿错时，选最短的能答对的调用方式。怎么都救不回来的题丢掉。提交示范（commit）的数量最多是救回示范（rescue）的 ρ 倍，多出的随机丢掉。ρ 沿用论文：MedQA 3，MMLU-Pro 和 GPQA 2，AQuA 1。论文的边际价值原则，每轮按当前模型的错误重新教
static否每轮都用 S₁ 当初训练用的那份标签文件，一字不改，从上一轮模型出发在这份标签上再做一次 SFT。重新收集数据有没有必要
success是使用和 dynamic 相同的题（同样按 ρ 截断），但每道题在所有最终答对的做法里随机选一个当示范。初稿已对时，直接提交和调用任一子模型后仍答对的做法都在候选里。不计调用成本时准确率能到多少
dynamic_sft是同 dynamic，但不做 GRPO：第 1 轮直接用 S₁，之后每轮只做 SFT。GRPO 本身贡献了多少

2实验设置

四个基准和论文相同。主实验跑 3 轮：dynamic 和 static，MedQA 另有 success。success 和 dynamic_sft 在 MMLU-Pro、GPQA、AQuA 上单独跑了消融（第 6 节），第 4–5 轮见第 7 节。每组只有一个随机种子。

每个模型在锁定测试上只测一次，测哪些模型在测之前就登记好。消融运行里按登记的理由又测了一次 S₁，逐题结果和主实验完全相同。dev 用来做每轮验收，也用来做第 3 节的复现对照和第 5 节的挑题分析；模型之间的准确率比较都用锁定测试。

重放准确率的算法：策略调用过的每道题，按强制调用它第一个子模型时的结果计分，其余题保留策略自己的结果。所以它和第 3 节的 dev 准确率不同，例如 MMLU-Pro 的 S₁ 是 59.0 对 63.0。倒数第二列是 2,000 次随机分配中准确率不低于策略的比例，和第 4 节配对检验的 p 不是同一个量；“高于随机”只看策略是否严格高于区间上沿，所以这一列为 0.04 的行也可能判为否。题数：MedQA、MMLU-Pro 200，AQuA 254，GPQA 100。表中略去的模型都不高于随机：MedQA 的 success，MMLU-Pro 第 5 轮的 static，AQuA 的 S₁、static（第 3、5 轮）和 dynamic_sft。有效答案率低于 0.90 的强制调用评估不参与重放（AQuA 各模型的 Extractor，AQuA static 的 Reasoner，GPQA success 和 MedQA 第 5 轮 static 的 Extractor），策略首先调用这些子模型的题保留策略本身的结果。dev 也参与了 GRPO 验收，所以这一节的结论不如锁定测试上的结论独立。

7.1 MedQA 上 dynamic 的初稿为什么变差

dynamic 的救回示范（call 行）把 manager 自己的错误草稿原样写进训练目标：响应是 DRAFT_ANSWER_X 加一次调用，X 就是模型答错时给出的字母，损失同时覆盖草稿和调用。模型答错时偏向给出 B，于是每轮的救回示范里 B 的比例越来越高，SFT 又把它学回去。static 每轮重用 S₁ 的那份标签，错误草稿里 B 只占 25%，而且不随轮数变化。

dynamic 在 dev 上给出 B 的题数（200 题，正确答案为 B 的有 47 题）5561677986

dev 上的数字取每轮 SFT 模型的评估（MedQA 的 GRPO 全部被拒，所以它就是该轮的最终模型）。锁定测试上同样：S₁ 在 500 题里给出 B 142 次，dynamic 第 5 轮 213 次（正确答案为 B 的有 113 题），配对 McNemar p < 10⁻¹⁹；static 第 5 轮 135 次。S₁ 初稿对、dynamic 第 5 轮初稿错的 46 题里，41 题 dynamic 给的是 B；它在其中 39 题上调用了子模型，救回 31 题，所以这个坍缩有一部分被调用补回来了。

  • AQuA 上同样的坍缩更严重，但被调用掩盖了。AQuA 的 ρ = 1，救回示范占训练行的多数，其中错误草稿为 B 的比例是 51–64%。dynamic 在锁定测试上给出 B 的比例从 S₁ 的 44% 升到第 3 轮 62%、第 5 轮 70%（正确答案为 B 的只有 23%），static 保持 46–47%。因为 AQuA 的 manager 对 80–90% 的题都调用 Verifier，初稿错了多半能被纠正，所以准确率没有像 MedQA 那样下降。
  • MMLU-Pro 和 GPQA 没有明显坍缩。MMLU-Pro 有 10 个选项，错误草稿分散，救回示范里最多的字母只占 26–33%；dynamic 在锁定测试上给出 B 的比例从 23% 变到 25%，初稿准确率不变。GPQA 的变化也在几个百分点以内。
  • 另一半损失是少调用。在 dev 上，dynamic 第 5 轮有 26 道初稿错且没调用的题，其中 17 道强制调用某个子模型就能答对（Verifier 能救 13 道）；static 第 5 轮是 23 道里 12 道，S₁ 是 20 道里 11 道。dynamic 第 5 轮的调用还转向了 Extractor（锁定测试上 92 次，Reasoner 38 次，Verifier 6 次），而 Extractor 是三个子模型里救回率最低的。
  • 这是选标签规则的问题，不是重新收集的问题。一个直接的修法是在救回示范里不对 DRAFT_ANSWER_X 计算损失，只训练它后面的调用决策；代码里 GRPO 的锚定损失已经有这种 route_only 掩码。这个修法已经跑过，见第 8 节。

跨第 3/4 轮的比较要谨慎。论文的 GRPO 题池在前三轮用完了，第 4–5 轮的 GRPO 题从新题里抽取。前三轮每批 256 道题里有 50–92 道出现在子模型 LoRA 的 SFT 数据里（实际调用的是基础子模型，但在这些题上调用几乎总是有用），第 4–5 轮只有 0–6 道。所以第 4–5 轮调用率的变化可能部分来自 GRPO 题构成的变化，不能直接说明多轮训练已经到头。

8修掉草稿反馈环之后：v2 和 v3

7.1 节找到的问题出在 SFT 的训练目标：dynamic 的救回示范（call 行）把 manager 自己的错误草稿 DRAFT_ANSWER_X 原样写进响应，损失同时覆盖草稿和后面的调用。我们给 SFT 加了一个开关 sft.draft_supervision，用两种掩码各把前三轮重跑了一遍：

  • v2（commit_rows）：call 行只对调用决策计算损失，草稿字母不计；直接作答的 commit 行照旧（草稿就是最终答案，仍然监督）。
  • v3（none）：所有行都不对草稿计算损失，SFT 只训练"调用谁 / 不调用"这个路由决策，也就是代码里 GRPO 锚定损失已有的 route_only 掩码。第 0 节的更新和下面的结论都以 v3 为准，v2 只作为中间版本记录（8.4 节）。

两次重跑都只做 SFT、不做 GRPO（第 6 节：GRPO 没有可靠贡献），两组各跑 3 轮：dynamic_sft 每轮用当前模型重新收集、重新选标签，static_sft 每轮复用 S₁ 的那份标签。重跑在一台新机器上进行，子模型的输出缓存从主实验恢复；S₁ 在这台机器上重新做了一次锁定测试：MedQA 78.4（主实验 78.6）、MMLU-Pro test 64.0（63.4）、test_paper 59.6（59.6）、GPQA 54.0（54.0）、AQuA 77.6（77.2），差别都不显著。本节和第 9 节所有"对 S₁"的比较都用这次重测。

8.4 v2 为什么偏向直接作答

v2 只在 call 行掩掉草稿，commit 行的草稿（也就是最终答案）照旧监督。这样每个 call 行只剩下几个 token 的调用损失，commit 行却仍有完整的答案损失，训练信号的重量偏向"直接作答"。效果在 dev 上很直接：MMLU-Pro 第 2 轮 dynamic 的调用率从 S₁ 的 0.31 掉到 0.07，第 3 轮回到 0.21；AQuA 的 static 每题调用从 0.78 降到 0.65，准确率比 S₁ 低 8.7 个点。v2 在 AQuA 上的 dynamic 是全部实验里 success 之外最高的数（82.7，对 S₁ +5.1，p = 0.012，每题调用 0.89），但同样的流程只换成 v3 的掩码就回到 78.0（对 v2 −4.7，p = 0.027），单次运行之间的这种差别我们不当作结论。v3 对所有行一视同仁，没有这个倾斜。

  • AQuA：dynamic 第 4 轮 dev 掉了 6.7 个点，第 5 轮锁定测试 71.7，对 S₁ −5.9（p = 0.009），对自己的第 3 轮 −6.3（p < 0.001）。初稿准确率 37.0（S₁ 36.2），B 的比例 39%（S₁ 44%），也不是草稿的问题。它在初稿错的题上调用 Verifier 的比例从第 3 轮的 0.88 降到 0.79（S₁ 0.85），纠正率从 0.47 降到 0.39；回放里不高于随机（p = 0.15）。static 第 5 轮 77.2，和 S₁ 持平，回放高于随机（p = 0.002）。
  • MMLU-Pro：dynamic 第 5 轮在 test 上 61.4（每题调用 0.30），比自己的第 3 轮低 3.0 个点（p = 0.04），对 S₁ −2.6（p = 0.18）；test_paper 58.6，对 S₁ −1.0（不显著）。static 第 5 轮 test 58.0，和第 3 轮一样（对 S₁ −6.0），test_paper 继续掉到 53.8（对第 3 轮 −5.2，p < 0.001）。第 5 轮 dynamic 仍高于 static：test +3.4（p = 0.049，McNemar 0.057），test_paper +4.8（p = 0.006）；在 104 道干净题上 dynamic 51.9、static 48.1、S₁ 53.8，都不显著。固定调用次数的回放里 dynamic 第 5 轮高于随机（60.5，区间 53.0–59.0，p = 0.003），static 不高于随机。dynamic 的初稿准确率不变（51.2，S₁ 50.8），B 的比例从 23% 升到 30%，调用从几乎只用 Verifier 变成 Reasoner / Verifier = 38 / 110。v1 里 dynamic 第 5 轮涨到 67.0（每题调用 0.44，含 GRPO）的结果在 v3 里没有复现：v3 的 dynamic 第 5 轮比它低 5.6 个点（p < 0.001），调用也少了三分之一。
  • 怎么理解。修掉草稿反馈环之后，dynamic 在后两轮的退步只剩一个来源：用当前模型重新收集的 400 道题算出来的 one-step 边际价值标签本身有噪声，而每轮都把它学进去。static 的标签固定，在 MedQA 和 AQuA 上不变或变好，在 MMLU-Pro 上停在比 S₁ 低 6 个点的位置。两种规则各有适用的地方：S₁ 的标签在 MMLU-Pro 上不够好，重新收集才有用（dynamic 第 5 轮虽然比第 3 轮低 3 个点，仍高于 static）；在 MedQA 和 AQuA 上 S₁ 的标签已经够好，再收集反而引入噪声。第 7 节末尾关于跨第 3 / 4 轮比较的提醒这里不再适用，因为 v3 没有 GRPO，第 4–5 轮和前三轮的训练题来源相同。

10局限和需要注明的地方

  • 单种子，未做多重比较校正。表中的 p 值都是单次比较的结果；标 † 的两处在 McNemar 下不显著。
  • MMLU-Pro 的 test_paper 和训练题重叠。dev 的 200 题全部在 test_paper 里，GRPO 每轮也在其中 31–50 道题上训练过，只有 104 题是干净的。test_paper 上的数字偏乐观，应以 test 和第 4.3 节的干净子集为准。
  • GPQA 太小。100 题的测试集上，6 个点的差也只是勉强显著（static − S₁，bootstrap p = 0.03，McNemar p = 0.07），success 比 dynamic 高 6 个点也不显著（p = 0.13）。训练题每轮重复使用，GPQA 的结果只能作参考。
  • 训练不能逐位复现。同一个模型重新评估，逐题结果完全相同；SFT 和 GRPO 重跑不一定相同。例如 MMLU-Pro 第 2 轮用同一份标签、同一个起点做的两次 SFT，dev 上分别是 60.0 / 0.275 和 60.5 / 0.255；GPQA 消融里第 1 轮的 GRPO 在第 8 步被回退到起点，而主实验中同一步训练到了第 64 步。所以消融和主实验的差别里也包含训练本身的随机波动。success 消融是单独的运行，它第 1 轮的 GRPO 和主实验不完全相同；dynamic_sft 不做 GRPO，直接从 S₁ 开始第 2 轮。
  • 无效答案的放行规则是中途加的。MMLU-Pro 第 5 轮 dynamic 的 SFT dev 评估因 1 道题没有给出可解析的答案而停下后，我们加了一条规则：如果唯一的问题是无法解析的答案、且有效答案率不低于 0.99，经操作者逐个确认后，这道题按答错计入，评估继续，报告中标为 ACKNOWLEDGED。规则只用于 SFT 模型的 dev 评估和锁定测试。按这条规则放行的有 4 次评估，各 1 道题：MMLU-Pro 第 5 轮 dynamic 的 SFT dev 评估和 test_paper 锁定测试，MedQA 第 4、5 轮 static 的 SFT dev 评估。另有 5 次 GRPO 候选在 dev 上出现 1–2 道无效答案，按验收条件直接被拒。为此 MMLU-Pro 第 5 轮中途更新过一次代码，只涉及这条规则的判断逻辑，变更记录在运行目录的 rsi_code_override.json 里；MedQA 第 4–5 轮开跑时规则已经存在。
  • dynamic 的救回示范会复制 manager 自己的错误草稿。这在 MedQA 和 AQuA 上造成了初稿向 B 坍缩（7.1 节）。第 1–7 节 dynamic 的所有结果都带着这个效应；修掉之后的结果在第 8、9 节。
  • v2 / v3 是另一台机器上的单次运行，没有 GRPO。子模型的输出缓存从主实验恢复，所以同一道题的子模型回答和主实验一致；S₁ 重测和主实验差 0.0–0.6 个点。v2 和 v3 各只跑了一次，v2 与 v3 在 AQuA 上 4.7 个点的差别说明单次运行之间的波动可以到这个量级。MMLU-Pro 开跑前的子模型一致性检查里，Reasoner 的相似度 0.49 低于原来 0.5 的门槛，我们把门槛降到 0.45 放行（相似度只是检查，不影响训练）。
  • v2 / v3 里按无效答案规则放行的评估：MedQA v2 第 3 轮 static 的 dev 评估、v3 第 3 轮 static 的 dev 评估和锁定测试、v3 第 4、5 轮 static 的 dev 评估，各 1 道题。确认在运行开始前就按同一条规则（只放行无效答案率不低于 0.99 的情况）预先记录，其他任何失败仍会停下。
  • 第 1 轮与论文的偏差是人工放行的，MedQA 的 S₁ 是替代模型（见第 2、3 节）。
  • dev 很小（100–254 题），而且参与了 GRPO 验收。模型之间的准确率比较都以锁定测试为准；第 5 节的挑题分析只在 dev 上做过，结论更弱。
